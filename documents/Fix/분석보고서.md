## 1. 설정 페이지 꾸미기

### 현재 상태

`frontend/src/app/(app)/settings/page.tsx` — 110줄짜리 단순 페이지.

- **프로필**: 아바타 + 이름 + 이메일 (읽기 전용)
- **캘린더 동기화**: "연동됨" 뱃지만 표시 (읽기 전용)
- **알림 설정**: "추후 업데이트 예정" 플레이스홀더
- **테마**: "추후 업데이트 예정" 플레이스홀더
- **로그아웃 버튼**

**문제점**: 설정 가능한 항목이 하나도 없음. DB에 `profiles.settings` (JSONB) 컬럼이 존재하지만 미사용.

### 원인

- 설정 CRUD API 미구현
- 테마 토글/알림 설정 등 인터랙티브 요소 부재
- 사이드바가 `bg-zinc-900`으로 하드코딩되어 테마 연동 불가

### 구현 계획

#### A. 백엔드 — 설정 API 추가

| 작업 | 파일 |
|------|------|
| `GET /api/settings` — 현재 설정 조회 | `backend/src/routes/settings.ts` (신규) |
| `PATCH /api/settings` — 설정 부분 업데이트 | 동일 |
| index.ts에 라우트 등록 | `backend/src/index.ts` |

설정 스키마 (JSONB):
```json
{
  "theme": "light" | "dark" | "system",
  "defaultCalendarView": "dayGridMonth" | "timeGridWeek" | "timeGridDay",
  "defaultReminderPriority": "low" | "medium" | "high",
  "language": "ko" | "en"
}
```

#### B. 프론트엔드 — 설정 페이지 리디자인

| 작업 | 파일 |
|------|------|
| 테마 토글 (Light/Dark/System) 구현 | `settings/page.tsx` |
| 기본 캘린더 뷰 선택 드롭다운 | 동일 |
| 기본 리마인더 우선순위 선택 | 동일 |
| 주요 지시사항(AI Instructions) 관리 섹션 | 동일 |
| 로그아웃 버튼 위치 조정 (위험 영역 분리) | 동일 |

#### C. 테마 시스템 연동

| 작업 | 파일 |
|------|------|
| ThemeProvider 추가 (next-themes) | `frontend/src/components/providers.tsx` |
| 사이드바 하드코딩 색상 → CSS 변수로 전환 | `frontend/src/components/sidebar.tsx` |
| globals.css `.dark` 클래스 활용 | `frontend/src/app/globals.css` |

## 2. AI 일정 요약 마크다운 렌더링

### 현재 상태

`frontend/src/app/(app)/home/page.tsx` 164-171줄:
```jsx
<p className="whitespace-pre-wrap text-sm leading-relaxed">
  {summary.summary}
</p>
```

- 일반 `<p>` 태그에 텍스트로만 출력
- Gemini가 마크다운 형식(볼드, 리스트, 헤더 등)으로 응답하지만 렌더링 안 됨

### 원인

1. **마크다운 렌더링 라이브러리 미설치** — `react-markdown` 등 없음
2. **Gemini 프롬프트에 마크다운 형식 지시 없음** — `summarizeSchedule()`에서 "자연스러운 한국어"만 요청
3. **채팅 패널도 동일 문제** — `chat-panel.tsx`의 `MessageBubble`도 `{msg.content}` 플레인 텍스트 출력

### 구현 계획

#### A. 라이브러리 설치

```bash
cd frontend && npm install react-markdown
```

#### B. 요약 영역 마크다운 렌더링

| 작업 | 파일 |
|------|------|
| `<p>` → `<ReactMarkdown>` 컴포넌트로 교체 | `home/page.tsx` |
| 마크다운 스타일링 (prose 클래스 또는 커스텀) | 동일 |

변경 전:
```jsx
<p className="whitespace-pre-wrap text-sm leading-relaxed">{summary.summary}</p>
```

변경 후:
```jsx
<ReactMarkdown className="prose prose-sm dark:prose-invert max-w-none">
  {summary.summary}
</ReactMarkdown>
```

#### C. 채팅 패널도 동일 적용 (선택)

| 작업 | 파일 |
|------|------|
| AI 응답 메시지에 마크다운 렌더링 적용 | `chat-panel.tsx` (MessageBubble) |

#### D. Gemini 프롬프트 개선 (선택)

| 작업 | 파일 |
|------|------|
| 요약 프롬프트에 마크다운 형식 지시 추가 | `backend/src/services/gemini.ts` |

## 3. 리마인더 CRUD 성능 개선

### 현재 상태

리마인더 생성/수정/완료 시 체감 딜레이가 큼.

### 원인 분석

#### 원인 1: Google Tasks + Supabase 순차 호출 (가장 큰 병목)

`backend/src/routes/reminders.ts`:

- **생성**: Google Tasks 생성 → 완료 대기 → Supabase insert (순차)
- **수정**: Supabase에서 기존 데이터 조회 → Google Tasks 업데이트 → Supabase update (3단계 순차)
- **완료**: Supabase 조회 → Google Tasks 상태 변경 → Supabase update (3단계 순차)
- **삭제**: Supabase 조회 → Google Tasks 삭제 → Supabase delete (3단계 순차)

현재 지연 구조:
```
생성: 지연 = Google API 시간 + Supabase 시간 (순차)
수정: 지연 = Supabase 조회 + Google API 시간 + Supabase 업데이트 (순차)
```

#### 원인 2: 프론트엔드 낙관적 업데이트 미적용 (생성/수정)

- **완료 토글, 삭제**: 낙관적 업데이트 적용됨 (양호)
- **생성**: 다이얼로그가 백엔드 응답 완료까지 로딩 상태 유지
- **수정**: 저장 후 전체 리마인더 목록 재요청 (`invalidateQueries`)

#### 원인 3: 수정/삭제/완료 시 불필요한 사전 조회

매 요청마다 `google_task_id`를 가져오기 위해 Supabase SELECT 실행.
프론트엔드가 이미 이 값을 알고 있음에도 전달하지 않음.

### 구현 계획

#### A. 백엔드 — 병렬 처리 전환

| 작업 | 파일 |
|------|------|
| 생성: Google Tasks + Supabase insert를 `Promise.all`로 병렬화 | `backend/src/routes/reminders.ts` |
| 수정: Google Tasks update + Supabase update 병렬화 | 동일 |
| 완료: Google Tasks status + Supabase update 병렬화 | 동일 |
| 삭제: Google Tasks delete + Supabase delete 병렬화 | 동일 |

생성 예시 — 변경 후:
```typescript
// google_task_id는 Google에서만 생성되므로 완전 병렬은 불가
// 하지만 수정/완료/삭제는 병렬 가능
const [googleResult, supabaseResult] = await Promise.all([
  updateGoogleTask(userId, listId, taskId, updates),
  supabaseAdmin.from('reminders').update(fields).eq('id', id)
]);
```

#### B. 프론트엔드 — google_task_id/google_list_id 전달

| 작업 | 파일 |
|------|------|
| 수정/삭제/완료 API 호출 시 body에 `google_task_id`, `google_list_id` 포함 | `reminders/page.tsx`, `reminders/[id]/page.tsx` |
| 백엔드에서 body 값 우선 사용, 없으면 기존 조회 폴백 | `backend/src/routes/reminders.ts` |

#### C. 프론트엔드 — 생성 시 낙관적 UX 개선

| 작업 | 파일 |
|------|------|
| 생성 다이얼로그: 요청 즉시 닫고 임시 항목 표시 | `create-reminder-dialog.tsx` |
| 수정: 저장 즉시 캐시 업데이트 (`setQueryData`) | `reminders/[id]/page.tsx` |

### 예상 개선 효과

| 작업 | 현재 | 개선 후 |
|------|------|---------|
| 수정/완료/삭제 백엔드 | Supabase 조회 + Google + Supabase 쓰기 (순차) | Google + Supabase 쓰기 (병렬), 사전 조회 제거 |
| 생성 UX | 다이얼로그 2-3초 로딩 | 즉시 닫힘, 백그라운드 완료 |
| 체감 지연 | ~1.5-3초 | ~0.5-1초 |
