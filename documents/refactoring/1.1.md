# CalenMate v1.1 — 성능 리팩토링 결과 & 향후 계획

## 1. 수행한 성능 최적화

### Backend

| 변경 | 파일 | 효과 |
|------|------|------|
| Auth 캐시 TTL 1분 → 3분 | `middleware/auth.ts` | Supabase auth 호출 ~3배 감소 |
| OAuth2 클라이언트 캐시 TTL 5분 → 15분 | `services/google-auth.ts` | Google API 인증 오버헤드 감소 |
| 토큰 리프레시 디바운싱 (500ms) | `services/google-auth.ts` | 빠른 연속 리프레시 시 Supabase 쓰기 감소 |
| Summary 캐시 TTL 5분 → 15분 | `routes/summary.ts` | Gemini API 호출 ~3배 감소 |
| Summary 캐시 무효화 함수 추가 | `routes/summary.ts` | AI 채팅으로 일정/리마인더 변경 시 즉시 반영 |

## 2. 코드 리뷰에서 발견된 추가 개선 사항

### 추후 수정 권장 (당장 필수는 아님)

#### 2-1. 디바운스 토큰 저장 — 프로세스 종료 시 유실 가능 (MEDIUM)
- **파일**: `backend/src/services/google-auth.ts`
- **문제**: `setTimeout(500ms)` 디바운스 중 프로세스가 종료되면 새 토큰이 DB에 저장되지 않음
- **해결**: `process.on('beforeExit')` 핸들러로 대기 중인 토큰 즉시 저장, 또는 디바운스를 100ms로 축소

#### 2-2. 백엔드 캐시에 크기 제한 없음 (MEDIUM)
- **파일**: `middleware/auth.ts`, `services/google-auth.ts`, `routes/summary.ts`
- **문제**: `Map` 기반 캐시가 무한 성장 가능 (토큰 버스트 공격 시)
- **해결**: 최대 엔트리 수 제한 (auth: 10,000, summary: 1,000) 및 LRU 방식 교체

#### 2-3. Summary 엔드포인트가 Google Tasks 데이터를 반영하지 않음 (LOW)
- **파일**: `backend/src/routes/summary.ts`
- **문제**: Supabase에서 직접 리마인더를 조회하므로 Google Tasks에서만 생성된 태스크가 누락됨
- **해결**: 리마인더 조회를 reminders 라우트와 같은 머지 로직으로 변경

#### 2-4. Home 페이지 날짜가 자정 이후 갱신되지 않음 (LOW)
- **파일**: `frontend/src/app/(app)/home/page.tsx`
- **문제**: `todayStart`/`todayEnd`가 렌더 시점에 한 번만 계산됨
- **해결**: `queryFn` 내부에서 날짜를 계산하거나, 자정 감지 로직 추가

#### 2-5. tasksApiClient가 executeAction에 전달되지만 실제 사용되지 않음 (LOW)
- **파일**: `backend/src/routes/chat.ts`
- **문제**: 프리페치된 Tasks 클라이언트가 service 함수까지 전달되지 않아 데드코드
- **해결**: google-tasks.ts 서비스 함수에 optional client 파라미터 추가, 또는 프리페치 제거

## 3. 리마인더 기능 개선 아이디어

### 3-1. 반복 리마인더 (Recurring Tasks)
- Google Tasks API는 반복을 직접 지원하지 않지만, Supabase 메타데이터에 반복 규칙 저장 가능
- 예: `recurrence: { type: 'daily' | 'weekly' | 'monthly', interval: 1, end_date?: string }`
- 완료 시 다음 반복 일정 자동 생성
- AI 프롬프트: "매주 월요일 운동 리마인더 만들어줘"

### 3-2. 하위 작업 (Subtasks)
- Google Tasks API가 `parent` 필드를 지원하므로 네이티브 하위 작업 구현 가능
- UI: 리마인더 상세 페이지에 체크리스트 형태의 하위 작업
- AI 명령: "장보기 목록에 우유, 빵, 계란 추가해줘"

### 3-3. 스마트 알림 (Smart Notifications)
- 현재 `notify` 필드가 있지만 실제 알림 발송 로직 없음
- 구현:
  - 백엔드 cron job이 `notify=true` & `due_date` 접근 시 알림
  - Web Push API 또는 이메일 발송
  - AI가 일정 밀도를 분석하여 "오늘 바쁜 하루네요. 우선순위 높은 것부터 해보세요" 같은 프로액티브 알림

### 3-4. 목록 공유 (Shared Task Lists)
- Google Tasks는 공유를 직접 지원하지 않지만, Supabase에 공유 메타데이터 저장 가능
- 특정 목록을 다른 사용자와 공유하여 협업

### 3-5. 리마인더 통계 대시보드
- 완료율, 평균 완료 시간, 우선순위별 분포 등
- "이번 주 12개 중 8개 완료 (67%)" 같은 AI 요약

## 4. 사용자 중심 서비스 아이디어

### 4-1. 아침 브리핑 (Morning Briefing)
- 매일 아침 오늘의 일정 + 리마인더 + 날씨를 AI가 요약
- Web Push 또는 이메일로 자동 발송
- 개인화된 어조 (사용자 instructions 기반)

### 4-2. 일정 충돌 감지
- 일정 생성 시 기존 일정과 시간이 겹치면 AI가 경고
- "14:00-15:00에 이미 '팀 회의'가 있어요. 시간을 변경할까요?"

### 4-3. 시간 블로킹 제안
- AI가 리마인더 목록을 분석하여 캘린더에 시간 블록을 자동 제안
- "오늘 오후 3시-4시에 '수학 공부하기'를 배치할까요?"

### 4-4. 주간 리뷰 자동 생성
- 매주 일요일/월요일에 지난 주 달성률 + 다음 주 계획 AI 요약
- 장기 목표 추적: "3주 연속 운동 리마인더를 완료했네요!"

### 4-5. 자연어 빠른 추가 (Quick Add)
- 홈 페이지에 입력창 하나로 "내일 3시 치과" 입력 시 AI가 자동으로 일정/리마인더 판단 및 생성
- 현재 AI 채팅과 유사하지만, 더 가볍고 빠른 UX

### 4-6. 위젯 / 모바일 최적화
- PWA 지원으로 홈 화면에 추가 가능
- 오늘의 일정/리마인더를 보여주는 미니 위젯

### 4-7. 캘린더 분석 인사이트
- "이번 달 회의가 전체 시간의 40%를 차지합니다"
- "가장 바쁜 요일: 화요일 (평균 5.2개 일정)"
- 번아웃 감지: 연속 과밀 일정 경고
