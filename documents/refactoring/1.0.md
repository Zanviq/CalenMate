# CalenMate 리팩토링 1.0 — 성능 최적화

**날짜**: 2026-03-31
**목표**: 데이터베이스 접근, AI 호출, 로그인 등에서 발생하는 딜레이 최소화

---

## 완료된 수정 사항

### Backend

#### 1. Google Calendar 클라이언트 캐싱 (`services/google-calendar.ts`)
- **문제**: 매 API 요청마다 DB에서 토큰 조회 + OAuth2 클라이언트 생성 + 토큰 강제 리프레시 수행 (약 500-2000ms 지연)
- **수정**: 유저별 OAuth2 클라이언트를 메모리에 5분 TTL로 캐싱. 불필요한 proactive 토큰 리프레시 제거 (Google 라이브러리가 401 시 자동 갱신)
- **효과**: 캐시 히트 시 DB 조회 + Google API 호출 완전 제거

#### 2. Auth 미들웨어 토큰 캐싱 (`middleware/auth.ts`)
- **문제**: 매 요청마다 `supabaseAdmin.auth.getUser(token)` 호출 (약 50-200ms 지연)
- **수정**: token→userId 매핑을 1분 TTL로 인메모리 캐싱
- **효과**: 동일 토큰의 연속 요청에서 Supabase 인증 호출 제거

#### 3. Chat 엔드포인트 병렬 데이터 페칭 (`routes/chat.ts`)
- **문제**: chat history → instructions → calendar events → reminders를 순차적으로 호출 (각 100-500ms, 총 400-2000ms)
- **수정**: `Promise.all`로 4개 데이터 소스를 동시에 페칭. executeAction에서 calendar client를 한 번만 생성하여 모든 action에 재사용
- **효과**: 4개 순차 호출 → 1개 병렬 호출 (가장 느린 호출 시간으로 수렴)

#### 4. Reminders 중복 소유권 체크 제거 (`routes/reminders.ts`)
- **문제**: PUT/DELETE에서 소유권 확인 쿼리 + 실제 작업 쿼리를 별도로 실행 (2번 DB 접근)
- **수정**: `.eq('user_id', userId)` 조건을 업데이트/삭제 쿼리에 포함시켜 단일 쿼리로 통합. `count: 'exact'` 또는 `PGRST116` 에러 코드로 404 감지
- **효과**: DELETE/UPDATE에서 DB 왕복 1회 감소

### Frontend

#### 5. API 클라이언트 세션 캐싱 (`lib/api.ts`)
- **문제**: 매 API 요청마다 `createClient()` + `getSession()` 호출 (약 20-100ms 지연)
- **수정**: Supabase 클라이언트 싱글톤화, 액세스 토큰 30초 TTL 캐싱, 401 시 자동 토큰 갱신 + 요청 재시도
- **효과**: 대부분의 API 요청에서 세션 조회 완전 제거

#### 6. Chat 컨텍스트별 메시지 보존 (`store/chat.ts`)
- **문제**: `setContext()` 호출 시 모든 메시지를 클리어하고 히스토리를 다시 로드 (페이지 전환마다 API 호출 + UX 저하)
- **수정**: `messagesByContext` 맵으로 컨텍스트별 메시지를 분리 저장. 이미 메시지가 있으면 히스토리 로드 생략
- **효과**: 페이지 전환 시 즉각적인 메시지 표시, 불필요한 API 호출 제거

#### 7. Chat 컴포넌트 메모이제이션 (`components/chat-panel.tsx`)
- **문제**: 새 메시지가 추가될 때 모든 MessageBubble/ActionBadges가 재렌더링. auto-scroll이 `querySelector`로 DOM 탐색
- **수정**: `React.memo`로 MessageBubble, ActionBadges 래핑. auto-scroll을 `useRef` 센티넬 요소 기반으로 변경
- **효과**: 메시지 추가 시 기존 메시지 재렌더링 방지, DOM 탐색 비용 제거

#### 8. Calendar 쿼리 키 최적화 (`app/(app)/calendar/page.tsx`)
- **문제**: `calendarActionCount`를 query key에 포함하여 AI 채팅으로 일정이 변경될 때마다 전체 캐시 무효화 + 새 캐시 엔트리 생성
- **수정**: query key에서 제거하고 `useEffect` + `invalidateQueries`로 전환
- **효과**: 기존 캐시 무효화 후 동일 키로 재페칭 (캐시 파편화 방지)

#### 9. Auth 토큰 무효화 연동 (`store/auth.ts`)
- **수정**: signOut 시 API 클라이언트의 캐시된 토큰도 함께 무효화

## 예상 성능 개선

| 영역 | Before | After | 개선 |
|------|--------|-------|------|
| Chat 메시지 전송 | ~2-4초 (순차 페칭 + 토큰 갱신) | ~0.5-1.5초 (병렬 + 캐시) | **50-70% 감소** |
| API 요청 인증 | ~50-200ms (매번 getUser) | ~0ms (캐시 히트) | **~99% 감소** |
| 캘린더 이벤트 조회 | ~500-2000ms (토큰 리프레시 포함) | ~200-500ms (캐시된 클라이언트) | **60-75% 감소** |
| 페이지 전환 (채팅) | API 호출 + 전체 리로드 | 즉각 표시 (캐시된 메시지) | **즉각 응답** |
| 프론트엔드 API 호출 | +20-100ms (세션 조회) | +0ms (캐시 히트) | **매 요청 절약** |

## 코드 리뷰 후 추가 수정 사항

| 이슈 | 심각도 | 수정 내용 |
|------|--------|-----------|
| Chat store `messages` getter가 Zustand에서 reactive하지 않음 | Critical | 죽은 getter 제거, 컴포넌트에서 직접 `messagesByContext[context]` 사용 |
| Auth cache 메모리 누수 | Critical | 60초마다 만료된 엔트리 정리하는 `setInterval` 추가 |
| 401 retry에서 `getSession()` 대신 `refreshSession()` 사용 | Important | 만료된 토큰을 확실히 갱신하도록 변경 |
| `setInterval`이 프로세스 종료를 차단 | Important | `.unref()` 추가 (google-calendar, auth 둘 다) |
| OAuth2Client 캐시 동작 주석 부재 | Important | 토큰 in-place 갱신 동작에 대한 주석 추가 |
| `loadHistory` 레이스 컨디션 | Suggestion | 요청 시점의 context를 캡처하고, 응답 시 context 변경 여부 확인 |
| Supabase 쿼리 에러 무시 | Suggestion | `Promise.all` 결과의 error 필드 로깅 추가 |

## 2차 리팩토링 완료 사항

### 5. Chat 히스토리 페이지네이션
- **Backend**: `/api/chat/history`에 `limit`, `before` 쿼리 파라미터 추가. 커서 기반 페이지네이션 (`created_at` 기준). 응답 형식 `{ messages, hasMore, total }`로 변경.
- **Frontend**: `loadOlderMessages()` 추가. IntersectionObserver로 상단 센티넬 감지 시 자동 로드. 기본 50개씩 로드.
- **효과**: 메시지가 많은 사용자도 초기 로드 빠름, 필요 시에만 이전 메시지 로드

### 6. Reminders 서버 사이드 필터링
- **Backend**: GET `/api/reminders`에 `?status=active|completed` 쿼리 파라미터 지원
- **Frontend**: 탭별로 서버에서 필터된 데이터 요청. 쿼리 키에 filter 포함 `['reminders', filter]`. 클라이언트 사이드 필터 제거.
- **효과**: 데이터 전송량 감소, 리마인더가 많을수록 효과 큼

### 7. Summary 엔드포인트 캐싱
- 유저별+period별 5분 TTL 인메모리 캐싱
- events + reminders 조회를 `Promise.all`로 병렬화
- **효과**: 캐시 히트 시 Gemini API 호출 완전 제거 (약 2-5초 절약)

### 8. 데이터베이스 인덱스 추가
- `user_instructions` 테이블 생성 (마이그레이션 미적용 상태였음)
- 4개 복합 인덱스 추가:
  - `idx_reminders_user_completed_due` — reminders 필터링/정렬 최적화
  - `idx_chat_messages_user_context_created` — chat history 페이지네이션 최적화
  - `idx_user_instructions_user_created` — instructions 조회 최적화
  - `idx_reminder_notes_reminder_user` — notes 조회 최적화

### 9. Optimistic Update 정리 (Reminders)
- toggle: `onSettled` invalidation 제거, optimistic update + onError rollback만 유지
- delete: optimistic update 추가 (즉시 UI에서 제거, 실패 시 롤백)
- **효과**: UI 깜빡임 제거

### 10. Backend 입력 유효성 검사 (Zod)
- `middleware/validate.ts` 생성: `validateBody(schema)` 미들웨어 팩토리
- 적용 라우트:
  - `POST /api/chat` — content/message 필수, context enum 검증, 길이 제한
  - `POST/PUT /api/reminders` — title 필수, priority enum, 길이 제한
  - `POST/PUT /api/calendar/events` — title/start/end 필수
  - `POST/PUT /api/instructions` — content 필수, 길이 제한
- **효과**: 잘못된 데이터가 DB에 저장되기 전 차단, 명확한 에러 메시지 반환
